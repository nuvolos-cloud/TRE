# Glossary

These are the terms used across the Nuvolos TRE documentation, in alphabetical order. Definitions describe Nuvolos TRE related concepts. Unless an entry says otherwise, a definition does not mean that a control, record or capability is available in any deployment. Status and evidence are set per deployment.

| Term                                            | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| :---------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Agent (agent principal)                         | An automated principal with its own identity and a named human sponsor. An agent can submit output for review. It never approves, promotes, signs or releases anything.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Asset owner (information asset owner)           | The party responsible for a dataset's classification, conditions, permitted uses and outputs under the customer's governance. Also called the information asset owner (IAO). This is not a platform role. It is not necessarily the data owner. Where the asset owner or its delegate holds release authority under the data agreement, that release role is the data owner. A data provider is a distinct role and may also hold this responsibility.                                                                                                                                                                                                                                                                                                                                                                                                |
| Audit trail                                     | The record of grants, approvals, refusals, exports, imports, operator access, agent actions and enforcement changes. It is tamper-evident, not tamper-proof. Evidence starts when capture starts. It is not the application or session text logs, which can contain sensitive content and have their own access and retention. Audit records use identifiers, not credentials or sensitive content. Decision metadata is itself scoped.                                                                                                                                                                                                                                                                                                                                                                                                               |
| Automated check                                 | A malware, format, integrity or disclosure check that reports evidence to a human. It never decides. If it did not run, the record says "check not performed". That is never a pass.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Batch job                                       | Analysis code submitted to run in an isolated environment with no interactive session. A batch job is a workload with a run record. It is not a login or a contained reviewer session. Locked and Enhanced use batch jobs as the researchers' working mode.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Break-glass                                     | The exceptional route for operator access to protected data. It needs a ticket, a second approver who is not the requester, a defined scope and an expiry. It is recorded.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Budget                                          | A financial limit on a resource pool.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Capability matrix                               | A mapping of allowed or refused actions to subjects, scopes and protection levels. One form is the per-API-route matrix, with allow, refuse or unverified for each entry. The term does not imply API routes only. An unverified entry is not a permit.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Checker                                         | A qualified, independent human who examines frozen output and records approve, return for changes or reject. The checker is not the requester, the run or agent principal, or the agent's sponsor. Where the page's policy adds an author exclusion, that applies too. In the output airlock this person is called the checker. A legal, security or other reviewer is not thereby a checker. Controlled needs at least one checker. Locked needs two, and both must approve. At Locked and Enhanced the checker works through a contained reviewer session. Checking is not release authority.                                                                                                                                                                                                                                                       |
| Checksum                                        | A value computed from a file's exact bytes and recorded for later comparison. It supports integrity checking. A mismatch shows that the bytes differ from those recorded. A match does not prove uniqueness, safety or approval. Collision resistance depends on the algorithm.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Class-A auto-pass                               | A historic L1-only proposal to fast-path eligible low-risk aggregate outputs after conclusive automated checks, controller sign-off and post-release audit. It is deferred. It is not an automatic release in the current TRE target, which requires human release. It is not available at Locked or Enhanced.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Close-out                                       | The governed end of a project. It covers ending access, resolving outstanding outputs, disposing of each data plane and recording what remains.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Cluster class                                   | An infrastructure placement and enforcement scope shared by clusters, such as a shared class or a dedicated deployment. Class-wide controls apply across it. Pages may use it for evidence and verdicts. It is not assumed identical to a deployment class.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Contained reviewer session                      | A checking-only interactive session at Locked and Enhanced, in which a checker inspects staged output. The checker cannot download or export unreleased material. Paste-in is blocked, and the session is logged. It is the sole interactive exception to the no-researcher-session rule. It is not a research session. Screenshot and retyping risk remain.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Control plane                                   | The platform layer that configures and enforces access, protection levels, requests and records. It is separate from the project workloads it governs. An application, model or database service is not the control plane merely because it runs remotely.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Controlled (L1)                                 | The TRE level for interactive research with governed import and export. Supported interactive applications run through the remote-desktop sidecar. Outbound internet is not blocked by default.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Credits                                         | The on-demand unit used to buy or draw resources such as elastic sizes, GPUs and extra storage. A subscription is required to use them.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Customer-managed keys                           | Encryption keys that the customer controls or manages for a covered data plane. The customer may supply them or generate them in a customer-controlled key management service. Enhanced supports them only where the deployment covers the entire in-scope storage set. They are distinct from platform-default key custody.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Data controller                                 | The party that determines the purposes and means of processing. It holds the duties that applicable law assigns to that role. It decides whether a project may use a dataset, and on what terms. A platform role never creates this status. The data controller is distinct from the data owner (release authority under the data agreement) and from the data custodian (intake and access under instruction). One party may hold more than one role.                                                                                                                                                                                                                                                                                                                                                                                                |
| Data custodian                                  | The person who operates intake, versioning and access under the data controller's or asset owner's instructions. The custodian approves imports as a human who is not the requester. Custody is operational. It confers neither the controller's duties nor release authority.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Data owner                                      | The party that holds release authority for a dataset under the data agreement. Its conditions govern that release. The data owner can name a delegate. It is not a platform role, and it may be a different party from the data controller or asset owner. Under the proposed profile policy, the data owner also approves new datasets at Locked (L2) and makes a separate import decision at Enhanced (L3).                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Data plane                                      | A distinct place where data can sit, such as instance files, tables, bulk storage, snapshots, backups, scratch space, logs or AI artefacts. The project policy covers each plane or refuses it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Data provider                                   | The party that supplies datasets or other inbound material. Supplying data does not assign information-asset-owner responsibility or data-owner release authority under the agreement. One party may hold more than one of these roles.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Dataset approval                                | The record that names a dataset. It records the data controller's agreement to access it, the asset owner's conditions and the approved version. It is separate from project approval. It binds that version, not every later copy or snapshot.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Dataset space                                   | A curated, static data asset that holds versioned datasets. It is a kind of space. It is neither a TRE project nor a working environment. Applications cannot run in it. Its named vintages are snapshot versions of the dataset, not project workspaces.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Decision                                        | The human outcome of a request: approve, return for changes or reject. A requester may also withdraw their own request.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Dedicated deployment                            | A deployment on its own infrastructure, not a shared cluster class. Enhanced requires one.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Delegate                                        | A named human who receives a specific authority, with a recorded scope and validity. A delegate never decides their own request.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Delivery link                                   | An identity-bound, expiring, single-use link that gives an authorised recipient their approved output. Redemption must authenticate the named recipient. Forwarding the link does not transfer entitlement. A failed transfer is not treated as delivered.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Deployment                                      | A specific combination of infrastructure, configuration and operating entity. TRE claims are always scoped to one deployment. The operating entity may be Nuvolos, the customer or another host. It is a different concept from the Nuvolos Organisation container and from the tenant scope.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Deployment class                                | The evidence scope for infrastructure-dependent controls and the verdict. Pages also use cluster class for this scope, and there is no settled definition of whether the two labels are identical. A deployment must state the class it uses. Controls are not assumed equal across classes.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Derived data                                    | Data created inside a project from approved inputs, such as cleaned tables, notebooks or intermediate files. It is writable. It does not change the approved input.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Effective access                                | The full view of who can reach a project, dataset or instance, and why. Each entry shows its origin: explicit, derived from another role or automatic. An origin that cannot be established is shown as unknown.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Effective actor (effective identity)            | The identity an action ran as when an approved delegation or impersonation was in effect. The true actor is the principal that actually triggered it. Where they differ, both are recorded. Accountability points to the true actor, and the action shows the effective identity.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Egress                                          | Data leaving a project. The output airlock governs the enumerated file routes. Other network and session paths have their own controls.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Elastic size                                    | A compute size with dedicated CPU and memory, and optionally GPUs. It consumes credits. The organisation must enable and fund it before members can use it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Enhanced (L3)                                   | The TRE level that adds dedicated deployment, tighter operator access and per-plane encryption to Locked. It is not operator-blind and not air-gapped.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Escalation clock                                | The deadline that escalates or expires an overdue request. An expired clock never releases material. Fail-closed handling applies.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Executor                                        | The person or service principal that carries out a governed action, such as a release, an import or a close-out deletion. An executor may also be the requester. Approval remains human and distinct from the requester and from every executor. No executor approves their own action.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Fail closed                                     | The rule that a missing or failed check, review or capacity leads to wait or no, never yes. A timeout never releases material.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Five Safes                                      | A framework that describes a TRE through five safes: people, projects, settings, data and outputs. No single control provides all five.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Governance assignment                           | A recorded assignment of accountability for a governed decision, such as approving a project, a dataset or an output, or operating the environment. It is not a platform role. It can exist outside Nuvolos. Server-side enforcement lets the platform enforce the assignment. It does not create the accountability.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Import airlock                                  | The governed route for data, code and other inbound material. It quarantines the material and runs configured checks. A custodian decides. The route then publishes a versioned read-only dataset.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Initial mode (L2/L3)                            | The first operating mode of Locked and Enhanced. Researcher analysis runs as submitted batch jobs, with no interactive researcher sessions. The contained reviewer session is a separate checking exception, not a research session.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Instance                                        | A work area inside a space that holds files and applications. It is the unit that carries instance file areas and instance roles. An instance is not a security boundary, and it is not a role. It shares its project's protection level. Its roles never approve a dataset or output.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Instance file area                              | The Workspace, Personal or Application file area inside an instance. Snapshots version supported contents of these areas. Coverage varies by data type.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Instance role                                   | The access role on an instance. Editor modifies state and runs applications. Viewer reads. Observer discovers. Viewer and observer are not proven read barriers without deployment evidence. These are platform access roles. They are not project or dataset approvals, and they create no release authority.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Key-custody map                                 | The record that states, for each storage type: which bytes are covered, who holds the key, how it is rotated, which subprocessor and region apply, and when it was last verified.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Legal reviewer                                  | A customer-appointed reviewer who assesses whether the customer's approval conditions are met at a policy-defined checkpoint. The reviewer records the decision where policy gives that authority. The role is scoped to specified projects and decision types. It gives no research-data access, and it is not an output checker.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Lifecycle record                                | The single authoritative current state of one process, such as a project, a request or a close-out. It states what the process is waiting for and who owns the next action.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Locked (L2)                                     | The TRE level for batch-only analysis of sensitive data. It has no interactive researcher sessions. The contained reviewer session is the sole interactive exception. It has no direct internet and no outside model or API calls.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Manifest                                        | The definitive list of every staged item in an output request, with a checksum for each. It is written once, at submission. Anything staged but not listed is a coverage gap. A manifest is a frozen coverage statement, not an approval.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Measured wait                                   | A statistic showing how long requests have taken. It is labelled as measured, not promised. It is shown to requesters. It is not a service commitment.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Not proven                                      | The verdict state for a control that lacks evidence in a deployment. It is never shown as green.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Open (L0)                                       | Ordinary Nuvolos, not a TRE. It carries no TRE assurance. It is listed only to show the difference from the TRE levels.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Operator                                        | The party that runs the infrastructure. This may be Nuvolos, the customer, a host or a provider, as the deployment agreement assigns. Operator access is accountable, scoped and recorded. The phrase "operators are never blind" means that privileged access is technically possible and cannot be excluded by the architecture. It does not mean that every operator routinely sees every project's data.                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Operator blindness                              | The property that operators cannot see or reach protected data. It is not promised at any protection level. Operator access is accountable, scoped and recorded instead.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Ordinary distribution                           | The platform's ordinary copy or share route for files, tables, applications or snapshots. This includes copies to another space or organisation. It carries no TRE approval, recipient binding or provenance. A TRE refuses it or redirects it into the governed import or export process.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Organisation                                    | The administrative container for a customer. It groups spaces, members, billing and administration. It is not a security boundary. It is a different concept from a tenant or a tenant cluster, whose isolation scope is deployment-specific.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Output airlock (also called the export airlock) | The governed route for results that leave a project through the enumerated file routes. It stages exact bytes and freezes a manifest. It runs advisory checks and requires human decisions. It delivers through a single-use link. It does not by itself close every network or session path.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Pause                                           | An operator or administrator action that blocks new agent submissions and dispatches. It does not stop a step that is already running.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Profile split                                   | The proposed L0–L3 split of role capabilities and decision requirements (the C01–C40 mapping). It is a proposal, not deployed behaviour. It is distinct from a protection level or profile.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Profile statement                               | A deployment-scoped statement of what the profile enforces. It states which controls are active, measured or still pending, which paths are uncovered, and the applicable evidence. Project-specific documentation states the controls that apply to that project. Some pages also call this a project statement. The sources do not establish that the two names always refer to the same record.                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Project                                         | The governed unit of work. It is one protected TRE space that carries one protection level, its project approval, roster and accountable people. Project decisions are separate from dataset approvals. An instance is a work area inside the project, not a project of its own.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Project administrator                           | The person or team that runs a project's operational review queue, assigns checkers and administers intake requests. This may be the project manager or a delegated administrator. The role does not grant space-administrator rights or release authority.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Project approval                                | The record that establishes a project's purpose, protection level, roster and accountable people. It does not approve any dataset. Dataset approval does that separately.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Project manager                                 | The delegated governance role that administers a project's operations. It holds invitation, role-change, lifecycle or resource-request abilities only where separately delegated. It has no automatic data access. It cannot approve its own changes.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Project organisation                            | The customer-side organisation accountable for a project's governance, including its approvals, agreements and oversight. It may correspond to a Nuvolos Organisation, or be a unit within one. The platform Organisation container is not itself a legal entity or the accountability.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Project owner                                   | The person accountable for a project's purpose and terms. The project owner nominates the project manager and owns the requirements and budget.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Promotion                                       | Moving a batch or agent run's output from its run output area into project files or a release path. It is never automatic. An agent never performs it. An authorised person promotes deliberately.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Protection level                                | One of four escalating sets of server-enforced protections: Open, Controlled, Locked and Enhanced. Also called a protection profile or TRE profile. Levels go up with re-approval. They never go down in place. "Server-enforced" says where enforcement sits. It does not mean every data path is covered. Each level's statement names its residual gaps. The role-split documents use "profile" in a different sense: a proposed per-level role and capability configuration (C01–C40). That is not the protection level itself.                                                                                                                                                                                                                                                                                                                   |
| Quarantine                                      | The per-request staging area where incoming material waits. No project workload can read, mount or run it. Staging confers no access.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Recipient                                       | The specific identity authorised under the data owner's policy to receive an approved output. Being the requester or a checker does not make someone a recipient.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Refusal                                         | A blocked action. It returns a plain reason and a way forward, such as a prefilled submission. Each refusal is recorded.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Release authority                               | The authority to let checked output leave a project. It belongs to the data owner or a properly delegated person. It does not come from an administrative role or from being a checker. At Locked and Enhanced, someone other than the checkers holds it. At Controlled, a checker may hold it only by separate delegation.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Remote-desktop sidecar                          | The companion container that renders an interactive application's interface in an isolated browser or desktop session. It streams only the screen to the user. At Controlled it is the normal path for supported interactive applications. At Locked and Enhanced it carries the contained reviewer session.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Requester                                       | The person who creates and submits a governed request, and who responds to revision requests. A requester never decides their own request.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Residual risk                                   | A risk that remains after the controls, such as screenshots, retyping, authorised insiders or shared infrastructure. Nuvolos states residual risks. It does not hide them.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Account                                         | A cost centre that holds a budget. Resources mapped to it charge their usage against that budget. The account related roles do not grant data access.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Roster                                          | A list of assignments or memberships for a project or space, with roles and, where recorded, the origin of each grant. A roster may or may not be a complete effective-access view. Listed relationships are not proof of effective access or data-use approval.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Run allowance                                   | The budget figure attached to a batch or agent run. Its effect varies by run type and deployment. By default, allowance s are hard caps.The deployment must state the actual enforcement.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Run principal                                   | The identity a batch or agent run executes as. It decides nothing. It is never a checker, approver or release authority. The requester or run principal cannot check that run's output. Where an agent runs, the run principal is distinct from the agent's sponsor. Whether it is the submitting person depends on the run mode and deployment.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Run record                                      | The record of a batch or agent run: progress, results and what the run consumed. It is not the audit trail. A batch run is not an interactive session. Session history and session logs are separate records.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| SATRE                                           | A specification for assessing an operated TRE. A SATRE assessment is a self-assessment of one deployment.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Server-side                                     | Enforced by the platform and its server or infrastructure components, at the decision point when the action is attempted. This can include platform-owned session components inside the project, such as the remote-desktop sidecar. It is not enforced by the user's browser or client. It can include control-plane, storage, network or other infrastructure enforcement, not only one service or the UI. It is not a client-side badge or a rollout setting. "Server-side" says where a control applies, not how far it reaches. One server-side route decision point does not protect another route. An application, model or database service is not the control plane merely because it runs remotely.                                                                                                                                         |
| Session                                         | A running application execution context with its own session identifier, compute usage, charge and logs. Not every session is interactive. Batch jobs may use session-like machinery, but they are not interactive researcher sessions. A login or identity-provider session is authentication only. It grants no project or dataset access by itself. It is not automatically known to have ended when a grant is revoked. An operator's break-glass access period may also be called a session. It is an accountability period, not an application session. Revocation reconciles related interactive sessions and credentials. A running batch or agent job is stopped by a separate action. Unless a page says otherwise, "session" means an application session. A contained reviewer session is the checking-only exception defined separately. |
| Session log                                     | The application output captured during a session. Also called an application log. It can contain sensitive data. It is visible to the session's starter or, in shared mode, to project members. It has a deployment-specific retention. It need not come from an interactive session. It is not the audit trail.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Shared responsibility                           | The division of duties between Nuvolos, the data controller, the operator of the deployment and researchers. Each deployment's agreements fix the division.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Snapshot                                        | A named point-in-time state of an instance's supported file areas, tables and application configuration. It carries no approvals. It is not proof of a complete backup, because coverage and restore differ by data plane. Table state may be re-cloned rather than restored. Creating a snapshot is not a transfer. Copying or distributing one to another space or project is a governed boundary crossing in a TRE.                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Space                                           | A self-contained project container in the Nuvolos hierarchy: organisation, then space, then instance. In a TRE, one protected project is one space, and the space carries its protection level. A dataset space is a different use of a space, not a project workspace. A space is an administrative and policy boundary. It is not proof of separate infrastructure.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Space administrator                             | The ordinary platform role that administers one space. It can create and delete instances, invite users and change space configuration. It holds inherited editor access on every instance. It is not the project manager, data owner or release authority. Its broad instance access needs separate authorisation. The target separates its administrative capabilities from data access.                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Sponsor                                         | The named human accountable for an agent. The sponsor creates and revokes the agent. An agent's authority is the lesser of the sponsor's rights and the project policy.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Stale                                           | The verdict state for evidence that has gone out of date.
